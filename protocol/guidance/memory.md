## Memory and reports

Only the LLM architect may write persistent memory. This includes project, user-level and
harness memory kept to guide future assignments, inside or outside the checkout. The architect
follows the applicable `AGENTS.md` and other governing rules for permission, approval and
notification. Holding the architect role does not grant permission to write by itself.

General coders, entry-level coders, the security engineer and the independent reviewer record
their findings and learnings in their assigned report: the card report, security report or
independent review. They do not write memory directly, through a tool or by delegation, even
when a finding is worth keeping. A generic instruction to remember something does not grant
write permission. If an instruction or harness behavior would require a memory write by one
of these roles, stop and ask the senior architect rather than writing.

Before each of these assignments starts, the architect's briefing names the exact report path
and says to put findings and learnings there and leave memory unchanged. The architect reviews
what comes back and decides what, if anything, belongs in memory. Normal stop lines and notes
still apply; the report does not replace them or authorize changes beyond the assignment.
